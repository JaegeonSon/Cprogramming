# 실습과제 1

## 1. 함수의 인자와 매개변수의 차이를 설명하라.

* 인자(Argument)는 함수를 호출할 때 함수에 전달하는 값이나 변수이다.
* 매개변수(Parameter)는 호출된 함수에서 인자로 전달된 값을 받아 저장하는 변수이다.
* 함수가 호출되면 인자의 값이 매개변수에 전달된다.

---

## 2. 함수가 호출될 때 컴퓨터에 의해 자동으로 실행되는 2가지를 설명하라.

1. 함수의 **매개변수를 위한 메모리 공간이 할당된다.**
2. 할당된 매개변수가 **전달된 인자의 값으로 초기화된다.**

---

## 3. 값에 의한 함수 호출방식의 문제점을 설명하라.

값에 의한 호출은 인자의 값을 매개변수에 **복사해서 전달하는 방식**이다.

따라서 호출한 함수의 변수와 호출된 함수의 매개변수는 서로 다른 변수이므로, 함수 내부에서 매개변수의 값을 변경하더라도 원래 인자의 값은 변경되지 않는다.

즉, **값에 의한 호출방식으로는 다른 함수에서 선언된 지역변수의 값을 직접 변경할 수 없다.**

---

## 4. 주소에 의한 함수 호출방식이 필요한 경우를 설명하라.

주소에 의한 호출은 변수의 값이 아니라 **변수의 주소를 함수에 전달하는 방식**이다.

다른 함수에서 선언된 지역변수의 값을 호출된 함수 내부에서 직접 변경해야 하는 경우 주소에 의한 호출방식이 필요하다.

변수의 주소를 전달하고 포인터를 이용해 해당 주소의 값을 변경하면 원래 변수의 값도 변경할 수 있다.

## 실행 결과가 원하는 대로 나오지 않는 이유

`add2(number)`와 같이 함수를 호출하면 `main` 함수의 `number` 변수 자체가 전달되는 것이 아니라, `number`에 저장된 **값이 매개변수 `value`에 복사되어 전달**된다.

17페이지의 메모리 그림을 기준으로 시간 순서에 따라 설명하면 다음과 같다.

1. **add2 함수 호출 전**

   * `main` 함수의 지역변수 `number`에는 입력받은 값 `15`가 저장되어 있다.
   * 이때 메모리에는 `number = 15`만 존재한다.

2. **add2 함수 호출 및 실행**

   * `add2(number)`가 호출되면 매개변수 `value`를 위한 새로운 메모리 공간이 만들어진다.
   * `number`의 값인 `15`가 `value`에 복사되어 `value = 15`가 된다.
   * 따라서 이 시점에는 `number = 15`, `value = 15`가 각각 별도의 메모리 공간에 존재한다.
   * `value += 2`가 실행되면 `value`의 값만 `15`에서 `17`로 변경된다.
   * `number`와 `value`는 서로 다른 변수이므로 `number`의 값은 여전히 `15`이다.

3. **add2 함수 종료 후**

   * `add2` 함수가 종료되면서 지역변수인 `value`의 메모리 공간은 사라진다.
   * `main` 함수의 `number`는 변경된 적이 없으므로 계속 `15`를 유지한다.

따라서 기존 코드는 **값에 의한 호출(Call by Value)** 방식을 사용하기 때문에 `add2` 함수 내부에서 `value`를 변경해도 `main` 함수의 `number`에는 영향을 주지 않는다.

원하는 결과를 얻으려면 `number`의 **주소를 함수에 전달**하고, 함수에서 포인터를 이용하여 해당 주소의 값을 직접 변경해야 한다.

# 실습과제 4
## 시간에 따른 메모리 상태

입력값을 다음과 같이 가정한다.

- `x = 10`
- `y = 20`
- `z = 30`

원하는 최종 결과는 다음과 같다.

`x = 20, y = 30, z = 10`

따라서 먼저 `x`와 `y`를 교환하고, 이후 `y`와 `z`를 교환한다.

---

### 1. swap 함수 호출 전

| 변수 | 저장된 값 |
| :---: | :---: |
| x | 10 |
| y | 20 |
| z | 30 |

```text
main 함수 메모리

┌─────────────┐
│ x  →  10    │
├─────────────┤
│ y  →  20    │
├─────────────┤
│ z  →  30    │
└─────────────┘
```

---

#### 첫 번째 swap 함수 호출

```c
swap(&x, &y);
```

`x`의 주소와 `y`의 주소가 각각 `px`, `py`에 전달된다.

즉,

- `px = &x`
- `py = &y`

가 된다.

---

### 2. 첫 번째 swap 함수 호출 직후

| main 함수 변수 | 값 |
| :---: | :---: |
| x | 10 |
| y | 20 |
| z | 30 |

| swap 함수 변수 | 값 |
| :---: | :---: |
| px | &x |
| py | &y |
| tmp | 미정 |

```text
├─────────────┤              ├─────────────┤

├─────────────┤              ├─────────────┤
│ z  →  30    │              │ tmp →  ?    │
└─────────────┘              └─────────────┘
```

---

### 3. 첫 번째 swap 함수 ① 실행

실행되는 문장:

```c
tmp = *px;
```

`px`는 `x`의 주소를 저장하고 있으므로 `*px`는 `x`의 값인 `10`이다.

따라서 `tmp`에 `10`이 저장된다.

| 변수 | 값 |

```text
└─────────────┘
```

### 4. 첫 번째 swap 함수 ② 실행

# 실습과제 5 
## 두 가지 함수 호출 방식의 차이 및 선택 이유

### 1. Call-by-value 방식

Call-by-value는 함수에 변수 자체가 아니라 **변수에 저장된 값을 복사하여 전달하는 방식**이다.

따라서 `HundredByValue` 함수의 매개변수 `num`과 `main` 함수의 `num`은 서로 다른 변수이다.

함수 내부에서 매개변수의 값을 변경해도 `main` 함수의 `num`에는 직접적인 영향을 주지 않는다.  
따라서 계산된 값을 `return`으로 반환한 뒤 다음과 같이 다시 저장해야 한다.

`num = HundredByValue(num);`

---

### 2. Call-by-reference 방식

Call-by-reference 방식에서는 변수의 **주소를 함수에 전달**한다.

`HundredByReference(&num)`과 같이 `num`의 주소를 전달하면 함수의 포인터 매개변수가 `num`의 주소를 가리키게 된다.

따라서 함수 내부에서 `*num`을 이용하면 `main` 함수의 원래 변수에 직접 접근할 수 있으며, 그 값을 100배 한 결과를 원래 변수에 바로 저장할 수 있다.

따라서 별도의 반환값을 다시 대입하지 않아도 된다.

---

### 3. 두 방식의 차이

| 구분 | Call-by-value | Call-by-reference |
| :---: | :--- | :--- |
| 전달하는 값 | 변수의 값 | 변수의 주소 |
| 원래 변수 직접 변경 | 불가능 | 가능 |
| 결과 전달 방법 | `return`을 이용 | 포인터를 이용하여 직접 변경 |
| 함수 호출 | `HundredByValue(num)` | `HundredByReference(&num)` |
| 매개변수 | 일반 변수 | 포인터 변수 |

두 방식 모두 올바르게 작성하면 `num`에 저장된 값의 100배를 얻을 수 있다.

예를 들어 `num`이 `10`인 경우 두 방식 모두 최종적으로 `1000`이라는 결과를 얻을 수 있다.

---

### 4. 선택 이유

이번 문제에서는 **num 변수에 저장되어 있는 값을 100배 한 값으로 직접 변경하는 것**이 목적이므로 Call-by-reference 방식이 문제의 의도에 더 적합하다고 판단하였다.

Call-by-value 방식도 반환값을 다시 `num`에 대입하면 동일한 결과를 얻을 수 있지만, 원래 변수의 값을 함수 내부에서 직접 변경하는 것은 아니다.

반면 Call-by-reference 방식은 `num`의 주소를 전달하여 함수 내부에서 원래 변수에 직접 접근하고 값을 변경할 수 있다.

따라서 **원래 변수 `num`의 저장값 자체를 함수에서 직접 100배로 변경한다는 관점에서는 Call-by-reference 방식을 선택하는 것이 적절하다.**
