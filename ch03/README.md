# 실습과제 1
## 1-1. 배열명의 의미를 설명하라.

배열명은 **배열의 첫 번째 요소의 주소**를 의미한다.

예를 들어 다음과 같은 배열이 있을 때,

```c
int a[5];
```

배열명 `a`는 첫 번째 요소의 주소인 `&a[0]`과 같다.

```c
a == &a[0]
```

배열명은 주소를 나타내지만 일반적인 포인터 변수와 달리 **주소 상수**이므로 다른 주소를 대입할 수 없다.

또한 배열의 자료형이 `int`라면 배열명 `a`가 가리키는 자료형은 `int`이고, 배열명의 자료형은 `int*`이다.

---

## 1-2. 배열표현과 포인터(주소) 표현의 변환 공식을 설명하라.

배열의 요소는 다음과 같이 포인터 표현으로 변환할 수 있다.

### 배열 요소의 값

```c
a[i] == *(a + i)
```

즉, `a + i`로 i번째 요소의 주소를 구한 후 `*` 연산자를 사용하면 해당 요소의 값을 얻을 수 있다.

### 배열 요소의 주소

```c
&a[i] == a + i
```

따라서 배열 표현과 포인터 표현의 관계는 다음과 같다.

| 구분 | 배열 표현 | 포인터(주소) 표현 |
| --- | --- | --- |
| 배열 요소의 값 | `a[i]` | `*(a + i)` |
| 배열 요소의 주소 | `&a[i]` | `a + i` |

---

## 1-3. 배열의 첫 번째 요소의 주소만 알면 모든 원소의 주소를 계산할 수 있다. 방법을 설명하시오.

배열의 모든 요소는 메모리에 **연속적으로 저장**된다.

배열의 첫 번째 요소의 주소를 `a`라고 하면 i번째 요소의 주소는 다음과 같이 구할 수 있다.

```c
a + i
```

실제 메모리 주소는 다음과 같이 계산된다.

```text
첫 번째 요소의 주소 + i × 자료형의 크기
```

예를 들어 `int`의 크기가 4바이트이고 `a[0]`의 주소가 1000이라면,

```text
a[0] : 1000
a[1] : 1004
a[2] : 1008
a[3] : 1012
```

가 된다.

따라서 배열의 첫 번째 요소의 주소와 배열 요소의 자료형을 알면 모든 원소의 주소를 계산할 수 있다.

---

## 1-4. 배열의 첫 번째 요소의 주소만 알면 모든 원소의 값을 계산할 수 있다. 방법을 설명하시오.

배열의 첫 번째 요소의 주소를 이용하여 각 요소의 주소를 구한 뒤 **간접참조 연산자 `*`**를 사용하면 해당 주소에 저장된 값을 구할 수 있다.

i번째 요소의 값은 다음과 같이 표현한다.

```c
*(a + i)
```

이는 배열 표현인 다음 문장과 같다.

```c
a[i]
```

예를 들어,

```c
int a[3] = {10, 20, 30};
```

이라면 다음과 같다.

```c
*a       == a[0] == 10
*(a + 1) == a[1] == 20
*(a + 2) == a[2] == 30
```

따라서 첫 번째 요소의 주소에서 원하는 요소의 위치만큼 이동한 후 간접참조하면 모든 원소의 값을 얻을 수 있다.

## 1-5. 포인터에 대해 가능한 연산의 종류와 의미를 설명하라.

포인터에 대해 가능한 주요 연산에는 **간접참조, 정수 덧셈, 정수 뺄셈, 증가, 감소 연산**이 있다.

### ① 간접참조 연산

```c
*p
```

포인터 `p`가 가리키고 있는 메모리 공간에 저장된 값을 의미한다.

### ② 정수 덧셈

```c
p + n
```

포인터가 현재 가리키는 주소에서 다음만큼 이동한다.

```text
n × 포인터가 가리키는 자료형의 크기
```

### ③ 정수 뺄셈

```c
p - n
```

포인터가 현재 가리키는 주소에서 다음만큼 이전으로 이동한다.

```text
n × 포인터가 가리키는 자료형의 크기
```

### ④ 증가 연산

```c
p++
```

포인터가 다음 요소의 주소로 이동한다.

예를 들어 `int* p`이고 `int`의 크기가 4바이트라면 `p++`을 수행했을 때 주소는 4바이트 증가한다.

### ⑤ 감소 연산

```c
p--
```

포인터가 이전 요소의 주소로 이동한다.

예를 들어 `int* p`이고 `int`의 크기가 4바이트라면 `p--`을 수행했을 때 주소는 4바이트 감소한다.

따라서 포인터의 덧셈이나 뺄셈은 단순히 주소값을 1씩 증가시키거나 감소시키는 것이 아니라 **포인터가 가리키는 자료형의 크기만큼 이동**한다.

---

## 1-6. 포인터 연산을 기존의 산술연산과 다르게 정의한 이유는 무엇일까?

포인터는 일반적인 숫자가 아니라 **특정 자료형이 저장된 메모리의 주소**를 나타내기 때문이다.

배열의 각 요소는 자료형의 크기만큼 떨어져서 연속적으로 저장되어 있으므로 포인터를 1 증가시킬 때 단순히 주소를 1바이트 증가시키는 것이 아니라 **다음 요소의 주소로 이동**해야 한다.

따라서 포인터 연산에서는 다음과 같이 자료형의 크기를 자동으로 고려한다.

```text
p + n
= 현재 주소 + n × 포인터가 가리키는 자료형의 크기
```

예를 들어,

```text
char*   → 1 증가하면 1바이트 이동
int*    → 1 증가하면 4바이트 이동
double* → 1 증가하면 8바이트 이동
```

과 같이 동작한다.

이처럼 포인터 연산을 기존의 산술연산과 다르게 정의하면 프로그래머가 자료형의 크기를 직접 계산하지 않아도 **배열의 다음 요소나 이전 요소의 주소를 쉽게 구할 수 있기 때문**이다.

## 3-1. 증감연산자 `a++`, `++a`의 차이를 설명하시오.

`a++`와 `++a`는 모두 변수 `a`의 값을 1 증가시키는 증감연산자이다.  
차이는 **증가시키는 시점**에 있다.

- `a++` : 후위 증가 연산자
  - 현재 값을 먼저 사용한 후, `a`의 값을 1 증가시킨다.

```c
int a = 10;
int b = a++;
```

## 3-2. 다음 코드의 문제점을 설명하시오.

```c
#include <stdio.h>

int main(void){

int a[] = { 10, 20, 30 }, i, sum = 0;

for (i = 0; i < 3; i++) sum += *a++;

printf("sum:%d\n", sum);

return 0;
}
```

문제가 되는 부분은 다음 문장이다.

```c
sum += *a++;
```

연산자 우선순위에 따라 위 문장은 다음과 같이 해석된다.

```c
sum += *(a++);
```

즉, 배열명 `a`가 가리키는 값을 더한 뒤 `a++`을 통해 배열의 다음 원소로 이동하려는 코드이다.

하지만 `a`는 포인터 변수가 아니라 **배열명**이다. 배열명은 배열의 첫 번째 원소의 주소를 나타내지만, 그 주소값 자체를 변경할 수 없는 **주소 상수**이므로 다음과 같은 연산은 할 수 없다.

```c
a++;
```

따라서 `sum += *a++;`는 배열명 `a`의 주소를 변경하려고 하기 때문에 오류가 발생한다.

이 문제를 해결하려면 배열의 주소를 저장할 수 있는 별도의 포인터 변수를 선언한 후, 그 포인터에 대해 증가 연산을 수행해야 한다.
