# 실습과제 1번

## 프로그램 개발 과정

### 1. 편집(Edit)

프로그래머가 구현하려는 기능에 맞게 C언어로 소스코드를 작성하는 단계이다. 에디터(Editor)를 사용하여 작성하며, 결과물은 확장자가 .c인 소스파일이다.

### 2. 선행처리(Preprocessing)

컴파일 이전에 선행처리기(Preprocessor)가 소스코드에 포함된 선행처리 명령문을 처리하는 단계이다. #include를 통해 헤더파일의 내용을 소스코드에 포함시키고, #define으로 정의된 매크로를 매크로 몸체로 치환한다. 선행처리가 완료된 결과도 C언어로 작성된 소스코드이다.

### 3. 컴파일(Compile)

컴파일러(Compiler)를 이용하여 선행처리가 완료된 C언어 소스코드를 기계어로 변환하는 단계이다. 이 과정에서 문법 오류 등을 검사하며, 정상적으로 완료되면 확장자가 .obj인 목적파일(Object File)이 생성된다.

### 4. 링크(Link)

링커(Linker)를 이용하여 컴파일 과정에서 생성된 목적파일과 표준 라이브러리 등의 필요한 파일을 연결하는 단계이다. printf, scanf와 같은 표준 라이브러리 함수의 호출과 실제 구현을 연결하며, 최종적으로 확장자가 .exe인 실행파일이 생성된다.

### 5. 실행(Execute)

로더(Loader)가 보조기억장치에 저장된 실행파일을 주기억장치(RAM)에 적재하고 CPU가 명령어를 수행하는 단계이다.

## 단계별 정리

| 단계 | 사용 프로그램 | 결과물 |
|---|---|---|
| 편집 | 에디터 | 소스파일(.c) |
| 선행처리 | 선행처리기 | 선행처리가 완료된 소스코드 |
| 컴파일 | 컴파일러 | 목적파일(.obj) |
| 링크 | 링커 | 실행파일(.exe) |
| 실행 | 로더 | 프로그램 실행 결과 |

## 파일 위치 확인

Visual Studio에서 프로젝트를 빌드한 후 파일 탐색기를 이용하여 소스파일(.c), 목적파일(.obj), 실행파일(.exe)의 위치를 확인한다.

- 소스파일(.c): 프로젝트 디렉터리
- 목적파일(.obj): 프로젝트의 중간 출력 디렉터리
- 실행파일(.exe): 프로젝트 또는 솔루션의 출력 디렉터리

※ 실제 파일 위치는 Visual Studio의 빌드 설정에 따라 달라질 수 있다.

# 실습과제 2번

## 1. C언어 표준 라이브러리 함수의 선언은 어디에 있는가?

printf, scanf 등의 표준 라이브러리 함수의 선언은 stdio.h와 같은 표준 라이브러리 헤더파일에 존재한다.

#include 지시자를 이용하면 선행처리 과정에서 헤더파일의 내용이 소스코드에 포함되므로 컴파일러가 함수의 반환형과 매개변수 등의 정보를 확인할 수 있다.

## 2. C언어 표준 라이브러리 함수의 호출은 어디에 있는가?

표준 라이브러리 함수의 호출은 프로그래머가 직접 작성한 C언어 소스파일(.c)에 존재한다.

예를 들어 main 함수 내부에서 printf("Hello World");를 작성하면 printf 함수를 호출하는 것이다.

## 3. C언어 표준 라이브러리 함수의 정의는 어디에 있는가? 또, 어떤 파일 형태로 존재하는가?

표준 라이브러리 함수의 실제 기능을 구현한 정의는 C언어 표준 라이브러리에 존재한다.

함수의 구현은 미리 컴파일된 목적파일(.obj)을 포함하는 라이브러리 파일(.lib)이나 동적 라이브러리(.dll) 등의 형태로 제공될 수 있다.

링크 과정에서 링커가 소스파일에서 호출한 함수와 라이브러리의 실제 구현을 연결하여 프로그램에서 해당 함수를 사용할 수 있도록 한다.

## 정리

- 함수 선언: 표준 라이브러리 헤더파일(.h)
- 함수 호출: 프로그래머가 작성한 소스파일(.c)
- 함수 정의: 컴파일된 표준 라이브러리

# 실습과제 3번

## 1. 매크로 상수를 사용하는 이유

매크로 상수는 복잡한 상수나 수식, 문자열 등에 의미 있는 이름을 부여하여 사용하기 위해 필요하다.

숫자를 직접 사용하는 대신 의미 있는 이름을 사용하면 코드의 가독성이 향상되고, 동일한 상수를 여러 곳에서 사용하는 경우 매크로 정의 부분만 수정하면 되므로 유지보수가 편리해진다.

또한 매크로 상수는 컴파일 이전의 선행처리 과정에서 매크로 몸체로 치환되므로 별도의 변수 저장 공간을 필요로 하지 않는다.

## 2. 매크로 상수를 사용한 예제

### 출처

Programiz - C Preprocessor and Macros
https://www.programiz.com/c-programming/c-preprocessor-macros

### 실행 결과

반지름을 입력하세요: 5
원의 넓이: 78.54

### 소스코드 설명

1. #include <stdio.h>
   선행처리 과정에서 printf, scanf 등의 함수 선언이 포함된 표준 입출력 헤더파일의 내용을 소스코드에 포함시킨다.

2. #define PI 3.1415
   원주율 3.1415를 PI라는 매크로 상수로 정의한다.

3. double radius, area;
   원의 반지름과 넓이를 저장하기 위한 실수형 변수를 선언한다.

4. scanf("%lf", &radius);
   사용자로부터 원의 반지름을 입력받아 radius 변수에 저장한다. 정상적으로 입력받지 못한 경우 프로그램을 종료한다.

5. area = PI * radius * radius;
   원의 넓이를 계산하여 area 변수에 저장한다. 선행처리 과정에서 PI는 매크로 몸체인 3.1415로 치환되므로 컴파일러는 다음과 같은 수식을 처리한다.

   area = 3.1415 * radius * radius;

6. printf("원의 넓이: %.2f\n", area);
   계산된 원의 넓이를 소수점 둘째 자리까지 출력한다.

## 3. 결론

매크로 상수를 사용하면 3.1415라는 숫자를 PI라는 의미 있는 이름으로 표현할 수 있어 코드의 가독성이 향상된다. 또한 원주율의 정밀도를 변경해야 할 경우 매크로 정의 부분만 수정하면 해당 매크로를 사용하는 모든 코드에 변경 사항이 반영되므로 유지보수가 편리하다.
